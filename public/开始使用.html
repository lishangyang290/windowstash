常见问题

01 · 先安装浏览器部分

把 WindowStash 放进 Chrome

Chrome 扩展是你保存当前窗口和标签页的入口。安装包已经准备好所有文件，不需要下载其他内容。

先确认安装包位置

你现在打开的 开始使用.html 与需要选择的 Chrome 扩展文件夹 Chrome Extension 在同一个文件夹。安装包结构应当是：

WindowStash-v0.2.0/
├── 开始使用.html
├── Chrome Extension/
├── WindowStash Companion.app
└── README.txt

在 Chrome 中加载扩展

  1. 打开 Chrome，新建一个标签页。
  2. 把下面的地址复制到 Chrome 地址栏并按回车。不要粘贴到搜索框或本教程页面里。
chrome://extensions
  1. 进入“扩展程序”页面后，找到右上角的 开发者模式 开关并打开。打开后，页面上方会出现几个新按钮。
  2. 点击页面上方的 加载已解压的扩展程序。
  3. Chrome 会打开文件选择窗口。回到刚才的 WindowStash-v0.2.0 安装包文件夹。
  4. 单击选中 Chrome Extension 文件夹，然后点击“选择”。选择这个文件夹本身，不要进入文件夹后再选某个文件。
什么时候算安装成功？Chrome 的扩展程序页面出现名为 “WindowStash” 的卡片，而且卡片上的开关处于开启状态。看到它以后再继续。

02 · 创建自己的数据空间

打开 Supabase，新建一个项目

Supabase 可以理解为 WindowStash 的私人在线数据空间，用来保存你的 Workspace。你不需要懂数据库，也不需要日常管理它。

打开 Supabase ↗

点击后会在新标签页打开 Supabase。如果没有 Supabase 账号，按页面提示注册；如果已经有账号，直接登录。登录成功后会进入 Dashboard。

第一步：进入 New project

  1. 确认你现在位于 Supabase Dashboard。
  2. 在页面中找到 New project 并点击，进入项目创建页面。

Organization

保持页面已经选择的默认 Organization。如果 Supabase 要求先创建一个，选择免费方案即可。

GitHub (optional)

不用选择，保持 Choose GitHub repository。

Project name

填写：

WindowStash

Database password

点击 Generate a password 生成强密码，并保存到密码管理器。这是数据库管理密码，不是 WindowStash 登录密码，后续配置 WindowStash 时不会使用。

Region

展开 Region，在 Asia-Pacific 中选择离你主要使用地点最近的区域即可。它决定数据存放在哪个地区；选好以后不需要再调整。

Security

三项依次设置为：Enable Data API 开启、Automatically expose new tables 关闭、Enable automatic RLS 开启。

ADVANCED CONFIGURATION 不用打开。

创建前照着这张表检查

  2. 等待 Supabase 自动进入新项目的 Dashboard，期间不要关闭页面。
什么时候算完成？页面已经进入 WindowStash 项目的管理后台，并且能看到左侧导航栏，就说明项目创建成功。

03 · 复制、粘贴、运行

初始化 WindowStash 数据库

你现在应该位于 WindowStash 项目的 Supabase 管理后台。下面的代码已经完整放在教程里，不需要在安装包中寻找 schema.sql。

查看初始化代码
-- WindowStash database initialization
-- Supabase Dashboard → SQL Editor → New query → paste this file → Run
-- Safe to run again: the table, indexes, trigger, grants, and policies are recreated idempotently.

create extension if not exists pgcrypto;

create table if not exists public.workspaces (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  name text not null check (char_length(name) between 1 and 200),
  status text not null check (status in ('active', 'review', 'revision', 'archived')),
  tabs jsonb not null default '[]'::jsonb check (jsonb_typeof(tabs) = 'array'),
  active_tab_index integer not null default 0 check (active_tab_index >= 0),
  content_hash text not null default '',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index if not exists workspaces_user_id_idx on public.workspaces(user_id);
create index if not exists workspaces_updated_at_idx on public.workspaces(updated_at desc);

create or replace function public.set_updated_at()
returns trigger
language plpgsql
security invoker
set search_path = ''
as $$
begin
  new.updated_at = now();
  return new;
end;
$$;

drop trigger if exists workspaces_set_updated_at on public.workspaces;
create trigger workspaces_set_updated_at
before update on public.workspaces
for each row execute function public.set_updated_at();

alter table public.workspaces enable row level security;

grant usage on schema public to authenticated;
grant select, insert, update, delete on table public.workspaces to authenticated;

drop policy if exists "Users can read own workspaces" on public.workspaces;
create policy "Users can read own workspaces"
on public.workspaces for select
to authenticated
using ((select auth.uid()) = user_id);

drop policy if exists "Users can create own workspaces" on public.workspaces;
create policy "Users can create own workspaces"
on public.workspaces for insert
to authenticated
with check ((select auth.uid()) = user_id);

drop policy if exists "Users can update own workspaces" on public.workspaces;
create policy "Users can update own workspaces"
on public.workspaces for update
to authenticated
using ((select auth.uid()) = user_id)
with check ((select auth.uid()) = user_id);

drop policy if exists "Users can delete own workspaces" on public.workspaces;
create policy "Users can delete own workspaces"
on public.workspaces for delete
to authenticated
using ((select auth.uid()) = user_id);
  1. 看 Supabase 页面最左侧的导航栏，找到并点击 SQL Editor。
  2. 进入 SQL Editor 后，看左侧的查询列表。在 Search queries... 搜索框右边找到这个小方形按钮 ＋；鼠标移到它上面时会显示 New query。点击它，新建一条查询。
  3. 点击后，页面中间会出现空白的代码编辑区域，上方通常会显示 New。如果进入 SQL Editor 时已经看到这个空白编辑区域，就不需要再点加号，可以直接继续。
  4. 点击本教程上方的 复制初始化代码，回到 Supabase 将代码完整粘贴到编辑区域，不要修改任何内容，然后点击右上角绿色的 Run 并等待执行结束。
什么时候算完成？结果区域没有出现红色的 Error，并显示执行成功或成功完成，就可以继续。如果以前运行过一次，也可以再次运行：这份代码支持重复执行，不需要先清空数据库。

04 · 从 Supabase 复制两项内容

找到 Project URL 和 Publishable Key

先打开 WindowStash 的连接页面，再从 Supabase 复制两项内容。

先找到 WindowStash 的输入框

如果是第一次使用，安装好扩展后打开 WindowStash，就会直接看到 Supabase Project URL 和 Publishable Key 两个输入框。

如果已经配置过、需要修改，打开 WindowStash 后台界面，点击顶部的 数据存储，即可重新打开这两个输入框。

回到 Project Overview，打开 Copy 菜单

看 Supabase 左侧导航菜单，点击第一项 Project Overview，回到 WindowStash 项目首页。如果侧栏没有展开，只看到图标，就点击最上面的房子图标。

  1. 点击项目地址右边的 Copy。
  2. 点击 Project URL，切换到 Chrome 中的 WindowStash，粘贴到 Supabase Project URL 输入框。
  3. 回到 Supabase，再次打开 Copy，点击 Publishable key。
  4. 回到 WindowStash，粘贴到 Publishable Key 输入框。

05 · 现在回到 Chrome

连接 Chrome 扩展

确认 Project URL 和 Publishable Key 已粘贴到对应输入框。

  1. 点击 测试连接。Chrome 如果询问是否允许 WindowStash 访问你的 Supabase 地址，请允许。
  2. 看到“✓ 连接成功”后，点击 保存并继续。
完成后的状态WindowStash 会进入注册或登录页面。测试失败时，回到 Supabase 的 Copy 菜单重新复制两项内容。

06 · 让 Workspace 可以同步

注册或登录 WindowStash

账户窗口默认显示登录页面。

  1. 第一次使用时，点击登录按钮下方的 还没有账号？注册。
  2. 进入注册页面后，填写邮箱和 WindowStash 登录密码，再点击 注册。
  3. 如果收到 Supabase 发来的验证邮件，按邮件提示完成验证，再回到 WindowStash 登录。
  4. 已经注册过的用户直接填写原来的邮箱和密码，点击 登录。
macOS 桌面应用只有登录按钮请使用刚才在 Chrome 扩展中注册的同一邮箱和密码登录。

07 · 把恢复入口放到 macOS 菜单栏

安装 macOS 桌面应用

WindowStash 的 macOS 桌面应用与本教程位于安装包的同一级目录，文件名为 WindowStash Companion.app。

  1. 回到包含 开始使用.html 的 WindowStash-v0.2.0 文件夹。
  2. 你会在旁边直接看到 WindowStash Companion.app。
  3. 打开 Finder 的“应用程序”文件夹，把 WindowStash Companion.app 拖进去。
  4. 复制完成后，从“应用程序”文件夹打开 WindowStash Companion。
如果 macOS 第一次阻止打开在 Finder 的“应用程序”中找到 WindowStash Companion，右键点击它，选择“打开”，再在弹窗中确认“打开”。不需要输入终端命令。

打开后，macOS 顶部菜单栏会出现 WindowStash 图标，或者屏幕会显示桌面应用的连接窗口。看到其中任一项就表示应用已经运行。

08 · 使用同一个 Supabase 项目

连接桌面应用并登录

桌面应用使用与 Chrome 扩展相同的 Project URL、Publishable Key 和 WindowStash 账号，不要创建第二个 Supabase 项目。

  1. 回到浏览器里的 Supabase WindowStash 项目，点击左侧导航菜单第一项 Project Overview。
  2. 打开项目地址右边的 Copy 菜单，点击 Project URL，回到桌面应用，粘贴到 Project URL 输入框。
  3. 再回到 Supabase 的 Copy 菜单，点击 Publishable key，粘贴到桌面应用的 Publishable Key 输入框。
  4. 点击 测试连接，连接成功后点击 保存并继续。
  5. 使用 Chrome 扩展中相同的 WindowStash 邮箱和登录密码登录。
完成后的状态桌面应用登录后会显示 Workspace 列表。刚开始列表为空是正常的。

09 · 开始真正使用

保存第一个 Workspace

一个 Chrome 窗口 = 一个 Workspace
场景 01

只记录现在的标签页
点击 Chrome 工具栏中的 WindowStash，再点击“保存当前状态”。当前 Chrome 窗口会保持打开。

场景 02

10 · 从菜单栏回到现场

恢复一个 Workspace

  1. 点击 macOS 顶部菜单栏里的 WindowStash 图标。
  2. 在展开的 Workspace 列表中找到你要继续的项目并点击。
  3. 如果对应的 Chrome 窗口已经打开，WindowStash 会切换到它；如果窗口已经关闭，WindowStash 会重新打开它和其中的标签页。
如果 Workspace 有很多标签页WindowStash 不会一次加载所有网页。暂时没使用的标签页会保持休眠，点击它时才加载，这是正常现象。

常见问题

Supabase 创建页面的 Security 选项怎么设置？

Enable Data API 开启，Automatically expose new tables 关闭，Enable automatic RLS 开启。初始化代码还会授予 WindowStash 所需的权限，并建立每位用户只能访问自己数据的保护规则。

Database password 和 WindowStash 登录密码有什么区别？

Database password 是 Supabase 数据库的管理密码，设置后保存到密码管理器，日常使用不会再填写。WindowStash 登录密码是你用邮箱注册 WindowStash 时设置的密码，Chrome 扩展和 macOS 桌面应用登录时都会使用。

找不到 Project URL 或 Publishable Key 怎么办？

点击 Supabase 左侧导航菜单第一项 Project Overview，回到项目首页，再打开项目地址右边的 Copy 菜单。如果首页没有这个菜单，从左侧导航底部进入 Project Settings → API Keys。

为什么恢复后有些网页没有立即加载？

为了避免大量标签页同时占用内存，WindowStash 会在你点击标签页时再加载网页。

为什么 Chrome 提示这是开发者模式扩展？

当前版本还没有发布到 Chrome Web Store，因此使用 Chrome 官方提供的“加载已解压的扩展程序”方式安装。

为什么 macOS 桌面应用第一次打不开？

当前测试版暂未进行 Apple notarization。请在 Finder 的“应用程序”中找到 WindowStash Companion，右键选择“打开”，再确认“打开”。

卸载 WindowStash 后 Workspace 会丢吗？

如果 Workspace 已同步到你自己的 Supabase，卸载 Extension 不会删除 Supabase 中的数据。重新安装后连接原来的 Supabase，再登录原来的账号，就可以重新同步。但如果你删除了 Supabase Project，WindowStash 无法恢复已删除的云端数据。
